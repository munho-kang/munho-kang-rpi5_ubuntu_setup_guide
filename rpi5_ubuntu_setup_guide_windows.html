A

SD카드 준비 (Claude Code)

1

준비하기

  • 노트북을 IOTCOSS1_5G에 연결합니다. 고정 IP 대역을 이 네트워크에서 읽어오기 때문입니다.
  • VPN이 켜져 있다면 끕니다. 네트워크 정보가 틀리게 읽힐 수 있습니다.
  • microSD 카드를 노트북(또는 카드 리더기)에 꽂습니다. 카드 안의 데이터는 전부 지워집니다.
  • PowerShell 창을 두 개 준비합니다. 하나는 Claude Code용, 하나는 명령을 직접 실행할 용도입니다. Windows Terminal을 쓰면 탭으로 나눌 수 있어 편합니다.
  • Raspberry Pi Imager를 설치합니다. 이미 있으면 넘어갑니다.
PowerShell
winget install -e --id RaspberryPiFoundation.RaspberryPiImager
이미지 기록(굽기)은 Claude Code가 아니라 Imager 프로그램으로 직접 합니다. Windows에서 명령으로 디스크에 직접 쓰는 것보다 훨씬 안전하고, 실수로 다른 디스크를 지울 위험이 거의 없습니다.
2

Claude Code 실행 후 프롬프트 입력

첫 번째 PowerShell 창에서 작업 폴더를 만들고 Claude Code를 실행합니다.

PowerShell 1
New-Item -ItemType Directory -Force "$env:USERPROFILE\rpi-setup" | Out-Null
cd "$env:USERPROFILE\rpi-setup"
claude

아래 프롬프트를 그대로 붙여 넣습니다. 도중에 Claude Code가 명령 실행 권한을 물으면 내용을 읽어 보고 허용하면 됩니다.

최종 프롬프트
라즈베리파이5(8GB)용 SD카드를 Ubuntu Server 24.04로 준비해줘.
노트북은 Windows 11이고 PowerShell을 쓸 거야. SD카드는 이미 꽂혀 있어.
작업 폴더는 %USERPROFILE%\rpi-setup 이야.

[안전 규칙 - 반드시 지킬 것]
1. `Get-Disk | Where-Object BusType -in 'USB','SD'`로 SD카드 후보를 보여주고
   디스크 번호, 용량, 이름을 정리해줘. 내가 확인해줄게.
2. 시스템 디스크(보통 0번, C: 드라이브가 있는 디스크)는 어떤 경우에도 건드리지 마.
3. Clear-Disk, Format-Volume, diskpart, dd 처럼 디스크 전체를 바꾸는 명령은 절대 직접 실행하지 마.
   이미지 기록은 내가 Raspberry Pi Imager로 직접 할 거야.
4. 관리자 권한이 필요한 명령은 실행하지 말고 완성된 명령어만 알려줘.
   내가 별도 PowerShell 창에서 실행하고 "완료"라고 알려줄게.

[1단계: 이미지 준비]
- https://cdimage.ubuntu.com/releases/24.04/release/ 에서 최신
  ubuntu-24.04.x-preinstalled-server-arm64+raspi.img.xz 를 작업 폴더에 받아줘 (curl.exe -L -O 사용).
- 같은 위치의 SHA256SUMS 값과 `Get-FileHash -Algorithm SHA256` 결과를 비교해서 보여줘.
  불일치하면 중단해.

[2단계: 고정 IP 결정]
- 노트북은 지금 IOTCOSS1_5G에 연결되어 있어.
  `Get-NetIPConfiguration -Detailed`로 노트북 IP, 프리픽스 길이, 게이트웨이, DNS를 확인해서 보여줘.
- 같은 대역에서 끝자리가 높은 번호(예: .200)를 고정 IP 후보로 제안하고,
  `Test-Connection -Count 2 후보IP`와 `arp -a`로 이미 쓰고 있지 않은지 확인해줘.
- 내가 승인하면 그 IP로 확정해.

[3단계: 기록 방법 안내]
- 기록은 내가 Raspberry Pi Imager로 직접 할게. 아래를 순서대로 안내해줘.
  - 장치: Raspberry Pi 5
  - 운영체제: 목록 맨 아래 "Use custom"(사용자 지정 이미지 사용) -> 받은 .img.xz 선택
  - 저장소: 위에서 확인한 SD카드 (용량과 이름을 대조해서 알려줘)
  - "OS 사용자 지정 설정을 적용하시겠어요?"가 나오면 반드시 "설정 없이 계속"을 고를 것.
    cloud-init 파일은 네가 직접 쓸 거니까 Imager 설정과 겹치면 안 돼.
  - 기록이 끝나면 Imager가 카드를 빼기 때문에, 카드를 뺐다가 다시 꽂아야 한다는 것
- Imager가 설치되어 있지 않으면 winget 설치 명령을 알려줘.

[4단계: cloud-init 설정 파일 작성]
- 내가 "완료"라고 하면 `Get-Volume -FileSystemLabel system-boot`로 드라이브 문자를 찾아줘.
- 기존 user-data, network-config는 작업 폴더의 backup\ 에 백업한 뒤 아래 내용으로 교체해줘.
- 두 파일 모두 줄바꿈은 LF, 인코딩은 BOM 없는 UTF-8로 저장해줘.
  Windows 기본 방식(CRLF, BOM)으로 저장하면 첫 부팅이 실패할 수 있어.
  CR을 제거한 문자열을 만들어서
  [IO.File]::WriteAllText($경로, $내용, (New-Object System.Text.UTF8Encoding $false)) 방식으로 써줘.

user-data (첫 줄은 정확히 #cloud-config):
- hostname: ras, manage_etc_hosts: true
- timezone: Asia/Seoul
- users: 사용자 ras 하나만 생성 (기본 ubuntu 사용자는 만들지 마)
  - plain_text_passwd: ras, lock_passwd: false
  - groups: adm, sudo, dialout, plugdev, video / shell: /bin/bash
- chpasswd: expire: false (첫 로그인 때 비밀번호 변경을 강제하지 않음)
- ssh_pwauth: true (SSH 비밀번호 로그인 허용)
- package_update: true, packages: [avahi-daemon] (ras.local 이름으로 접속하기 위함)

network-config (netplan v2 형식):
- wifis 아래 wlan0, dhcp4: false
- addresses: [확정IP/프리픽스]
- routes: to: default, via: 게이트웨이 (gateway4는 deprecated라 사용 금지)
- nameservers: 게이트웨이, 8.8.8.8
- regulatory-domain: KR
- access-points: "IOTCOSS1_5G", password: "Coss0603"

[5단계: 검증 및 마무리]
- 작성한 user-data와 network-config 전체 내용을 보여주고 YAML 문법을 검사해줘.
  (시스템 Python에 패키지를 직접 설치하지 말고, 필요하면 임시 가상환경을 써)
- 두 파일에 CR(0x0D)과 BOM이 없는지 확인해서 보여줘.
- 문제가 없으면 `Write-VolumeCache -DriveLetter <문자>`로 저장을 마무리하고,
  파일 탐색기에서 드라이브를 우클릭 -> 꺼내기 하라고 알려줘.
- 마지막에 확정된 고정 IP와 접속 명령(ssh ras@IP)을 요약해줘.
3

이미지 다운로드와 체크섬 확인

Claude Code가 이미지를 받고 SHA256 값을 비교해 보여줍니다. 두 값이 같다는 결과만 확인하면 됩니다. 이미지는 1GB가 넘어서 네트워크에 따라 몇 분 걸립니다.

체크섬은 파일이 받는 중에 깨지지 않았는지 확인하는 지문 같은 값입니다. 값이 다르면 다시 받아야 합니다.
4

고정 IP 승인

Claude Code가 네트워크 정보와 IP 후보를 보여줍니다. 아래 세 가지를 확인하고 승인하세요.

  • 후보 IP가 노트북 IP와 같은 대역인지 봅니다. 예를 들어 노트북이 192.168.0.23이면 후보도 192.168.0.x여야 합니다.
  • Test-Connection 결과가 False여야 합니다. 응답이 오면 이미 누가 쓰고 있는 IP입니다.
  • 게이트웨이 주소가 보통 .1 또는 .254로 끝나는지 봅니다.

승인했다면 아래 칸에 입력해 두세요. 이후 명령어에 자동으로 반영됩니다.

여기에 입력하면 이 아래 명령어들에 자동으로 들어갑니다.
공유기 관리 권한이 있다면 공유기의 DHCP 범위 밖 번호를 고르는 게 가장 안전합니다. 공용 네트워크라 알 수 없다면 .200 이상의 높은 번호가 대체로 안전합니다.
5

SD카드 확인 (가장 중요)

Imager에서 엉뚱한 디스크를 고르지 않도록, 먼저 SD카드의 번호와 용량을 확인해 둡니다. Claude Code가 아래 명령의 결과를 보여줍니다.

PowerShell 2
Get-Disk | Where-Object BusType -in 'USB','SD' | Format-Table Number, FriendlyName, @{n='GB';e={[math]::Round($_.Size/1GB,1)}}, BusType
예시 출력
Number FriendlyName                GB BusType
------ ------------                -- -------
     2 Generic MassStorageClass  63.9 USB
  • BusType이 USB 또는 SD로 표시되는지 확인합니다.
  • 용량이 SD카드 용량과 비슷한지 확인합니다. 64GB 카드는 약 63.9GB로 표시됩니다.
  • Number가 0이 아닌지 확인합니다. 0번은 Windows가 설치된 내장 디스크입니다.
  • 헷갈리면 SD카드를 뺐다가 다시 꽂고, 목록에서 사라졌다 나타나는 줄을 찾으세요.

여기서 확인한 이름과 용량을 기억해 두세요. 다음 단계에서 Imager의 저장소 목록에서 같은 것을 고르면 됩니다.

6

이미지 기록 (Raspberry Pi Imager로 직접)

Raspberry Pi Imager를 실행하고 아래 순서대로 고릅니다.

  • 장치: Raspberry Pi 5
  • 운영체제: 목록 맨 아래 Use custom(사용자 지정 이미지 사용) → %USERPROFILE%\rpi-setup 폴더의 ubuntu-24.04...raspi.img.xz 선택
  • 저장소: 5단계에서 확인한 SD카드. 이름과 용량을 한 번 더 대조합니다.
  • 다음 → “OS 사용자 지정 설정을 적용하시겠어요?”가 나오면 설정 없이 계속을 누릅니다.
  • “카드의 모든 데이터가 지워집니다” 경고에 예를 누르면 기록이 시작됩니다. 확인(verify)까지 보통 5~15분 걸립니다.
저장소 목록을 한 번 더 보세요. 5단계에서 확인한 용량·이름과 다르면 진행하지 마세요. 잘못된 디스크에 쓰면 복구할 수 없습니다.
“설정 없이 계속”이 중요합니다. Imager에서 사용자·Wi-Fi를 설정하면 Claude Code가 쓸 cloud-init 파일과 겹쳐서 부팅이 꼬일 수 있습니다.
  • 기록이 끝나면 Imager가 카드를 빼버립니다. SD카드를 뽑았다가 다시 꽂으세요.
  • “이 디스크를 사용하려면 먼저 포맷해야 합니다” 팝업이 뜨면 취소를 누릅니다. 리눅스용 파티션이라 Windows가 못 읽는 것이고 정상입니다.
  • 파일 탐색기에 system-boot 드라이브가 보이면 성공입니다. 그 드라이브 문자를 아래 칸에 입력하세요.
SD카드가 잡힌 드라이브 문자입니다 (D: → D).

기록이 끝나고 카드를 다시 꽂았으면 Claude Code에 “완료”라고 알려줍니다.

명령으로 기록하고 싶다면 관리자 권한 PowerShell에서 아래처럼도 됩니다. PhysicalDrive 뒤 숫자는 5단계의 Number입니다. 숫자를 틀리면 그 디스크가 지워지니, 익숙하지 않다면 위의 Imager 방법을 쓰세요.
관리자 PowerShell
& "${env:ProgramFiles(x86)}\Raspberry Pi Imager\rpi-imager.exe" --cli "$env:USERPROFILE\rpi-setup\ubuntu-24.04-preinstalled-server-arm64+raspi.img.xz" "\\.\PhysicalDrive2"
7

설정 파일 확인 후 꺼내기

Claude Code가 user-data와 network-config를 작성해 보여줍니다. 직접 한 번 더 확인하고 싶다면 두 번째 PowerShell 창에서 실행하세요.

PowerShell 2
Get-Content D:\user-data -TotalCount 3
Get-Content D:\network-config
  • user-data 첫 줄이 #cloud-config입니다.
  • network-config에 고정IP/24 같은 주소, IOTCOSS1_5G, regulatory-domain: KR이 들어 있습니다.
  • SSID 대소문자와 밑줄(_5G)이 정확합니다. 한 글자라도 틀리면 연결되지 않습니다.

Windows가 줄바꿈을 자기 방식(CRLF)으로 넣었으면 첫 부팅이 실패할 수 있습니다. 아래 명령이 OK를 출력해야 합니다.

PowerShell 2
'user-data','network-config' | ForEach-Object { $f="D:\$_"; if ((Get-Content -Raw $f) -match "`r") { "$_ : CRLF 있음 - 다시 저장해야 함" } else { "$_ : OK" } }

확인이 끝나면 저장 내용을 카드에 확실히 밀어 넣고 꺼냅니다.

PowerShell 2
Write-VolumeCache -DriveLetter D

그다음 파일 탐색기에서 system-boot 드라이브를 우클릭 → 꺼내기를 누르고 카드를 뽑습니다.

B

부팅과 원격 접속

8

첫 부팅

  • microSD 카드를 라즈베리파이5 뒷면 슬롯에 끼웁니다.
  • 전원을 연결합니다. 공식 27W(5V 5A) USB-C 어댑터를 권장합니다. 일반 충전기를 쓰면 USB 전력이 제한된다는 경고가 뜰 수 있습니다.
  • 5분 정도 기다립니다. 첫 부팅 때 cloud-init이 사용자 생성, Wi-Fi 설정, avahi 설치를 진행합니다. 이 동안 초록 LED가 불규칙하게 깜빡입니다. 중간에 전원을 뽑지 마세요.
9

SSH 접속

노트북이 같은 Wi-Fi(IOTCOSS1_5G)에 연결되어 있는지 확인한 뒤, 먼저 응답이 오는지 봅니다.

노트북 PowerShell
ping -n 3 고정IP

응답이 오면 접속합니다.

노트북 PowerShell
ssh ras@고정IP
  • 처음 접속하면 Are you sure you want to continue connecting가 나옵니다. yes를 입력합니다.
  • 비밀번호 ras를 입력합니다. 화면에는 표시되지 않습니다.
  • 프롬프트가 ras@ras:~$로 바뀌면 접속 성공입니다.

IP 대신 이름으로도 접속할 수 있습니다. avahi 설치가 끝난 뒤부터 되고, Windows에서는 안 될 때도 있습니다.

노트북 PowerShell
ssh ras@ras.local
10

접속 후 점검

라즈베리파이에 접속한 상태에서 아래를 차례로 실행합니다.

라즈베리파이 (ras@ras)
cloud-init status --wait        # status: done 이 나와야 함
hostname                        # ras
ip -4 addr show wlan0           # 고정 IP가 잡혔는지 확인
ping -c 3 8.8.8.8               # 인터넷 연결 확인
sudo apt update && sudo apt full-upgrade -y
sudo reboot

업데이트는 처음에 10분 이상 걸릴 수 있습니다. 재부팅 후 1분쯤 지나 다시 접속하세요.

비밀번호 ras는 공용 네트워크에서 쉽게 뚫립니다. 접속한 뒤 passwd로 더 긴 비밀번호로 바꾸는 걸 권장합니다.

문제 해결

ssh 명령을 찾을 수 없다고 나옴

Windows에 SSH 클라이언트가 꺼져 있는 경우입니다. 설정 → 시스템 → 옵션 기능 → 기능 보기에서 OpenSSH 클라이언트를 추가하세요. 관리자 PowerShell에서 아래 명령으로도 됩니다.

관리자 PowerShell
Add-WindowsCapability -Online -Name OpenSSH.Client~~~~0.0.1.0
Claude Code가 관리자 권한이 필요한 명령에서 멈춰 있음

Claude Code 안에서는 관리자 권한 승인 창을 누를 수 없습니다. Esc로 멈춘 뒤 “관리자 권한이 필요한 명령은 명령어만 알려줘”라고 다시 요청하고, 관리자 권한으로 띄운 두 번째 PowerShell 창에서 직접 실행하세요.

Imager의 저장소 목록에 SD카드가 안 보임

카드 리더기를 뺐다가 다시 꽂고, USB 허브를 거치지 말고 노트북에 직접 연결해 보세요. Get-Disk 결과에도 안 보이면 리더기나 카드 문제입니다. Imager를 관리자 권한으로 실행하면 잡히는 경우도 있습니다.

기록 후 system-boot 드라이브가 보이지 않음

Imager가 기록 후 카드를 빼기 때문입니다. SD카드를 뽑았다가 다시 꽂으세요. “포맷해야 합니다” 팝업은 취소를 누릅니다. 그래도 안 보이면 아래로 확인하세요.

PowerShell
Get-Volume -FileSystemLabel system-boot

드라이브 문자가 비어 있으면 디스크 관리(Win+X → 디스크 관리)에서 system-boot 파티션에 문자를 지정하면 됩니다.

부팅했는데 사용자도 Wi-Fi도 설정이 안 되어 있음

설정 파일이 Windows 방식(CRLF 줄바꿈, BOM)으로 저장되면 cloud-init이 읽지 못할 수 있습니다. SD카드를 다시 꽂고 7단계의 확인 명령을 실행해 보세요. CRLF 있음이 나오면 Claude Code에 “user-data와 network-config를 LF, BOM 없는 UTF-8로 다시 저장해줘”라고 요청하세요.

Imager의 OS 사용자 지정 설정을 함께 쓴 경우에도 충돌할 수 있습니다. 그럴 때는 6단계를 “설정 없이 계속”으로 다시 진행하세요.

ping에 응답이 전혀 없음

먼저 2~3분 더 기다리고, 그래도 안 되면 전원을 한 번 껐다 켜세요. Ubuntu는 첫 부팅 때 Wi-Fi가 늦게 잡히는 경우가 있어 재부팅으로 해결되는 일이 많습니다.

계속 안 되면 모니터와 키보드를 연결해 ras / ras로 로그인한 뒤 확인합니다.

라즈베리파이 (직접 연결)
ip a show wlan0
sudo cat /etc/netplan/50-cloud-init.yaml
sudo netplan apply

wlan0에 IP가 잡혀 있는데도 노트북에서 접속이 안 된다면, 네트워크에 AP 격리(기기끼리 통신 차단)가 켜져 있을 수 있습니다. 네트워크 관리자에게 문의하거나 랜선을 노트북과 직접 연결해 우회하세요.

Permission denied (비밀번호가 틀렸다고 나옴)

cloud-init이 아직 사용자를 만들지 않았을 가능성이 큽니다. 몇 분 더 기다린 뒤 다시 시도하세요. 그래도 안 되면 SD카드를 노트북에 다시 꽂아 user-data의 첫 줄이 #cloud-config인지, 들여쓰기가 맞는지 확인합니다.

REMOTE HOST IDENTIFICATION HAS CHANGED 경고

SD카드를 새로 구우면 서버 키가 바뀌어서 나오는 경고입니다. 예전 기록을 지우고 다시 접속하세요.

노트북 PowerShell
ssh-keygen -R 고정IP
ssh-keygen -R ras.local
ras.local로는 접속이 안 되고 IP로는 됨

Windows는 .local 이름 찾기(mDNS)가 불안정합니다. 고정 IP로 접속하는 게 가장 편합니다.

이름으로 꼭 접속하고 싶다면 Apple의 Bonjour(Bonjour Print Services for Windows)를 설치하면 대체로 해결됩니다. 라즈베리파이 쪽에 avahi가 빠졌을 수도 있으니 IP로 접속한 뒤 sudo apt install -y avahi-daemon도 확인하세요.

터미널에서는 되는데 VS Code만 연결이 안 됨

먼저 PowerShell에서 ssh ras가 되는지 확인하세요. 그게 된다면 VS Code의 Remote - SSH 확장이 다른 ssh를 쓰고 있을 수 있습니다. 설정에서 remote.SSH.path를 C:\Windows\System32\OpenSSH\ssh.exe로 지정하고 VS Code를 다시 실행하세요.

회사·학교 노트북이라면 방화벽이나 보안 프로그램이 막는 경우도 있습니다.

고정 IP가 다른 기기와 충돌함

SD카드를 노트북에 꽂고 D:\network-config의 addresses만 다른 번호로 바꾸면 됩니다. 이미 부팅한 뒤라면 라즈베리파이에서 /etc/netplan/50-cloud-init.yaml을 수정하고 sudo netplan apply를 실행하세요.

대안: Imager 설정만으로 하기

Claude Code 과정이 막히면 Imager의 설정 기능만으로도 대부분 됩니다. 장치는 Raspberry Pi 5, OS는 Other general-purpose OS → Ubuntu → Ubuntu Server 24.04.x LTS (64-bit)를 고릅니다. 저장소에서 SD카드를 선택한 뒤 OS 사용자 지정 설정에서 hostname, 사용자, 비밀번호, Wi-Fi(SSID·비밀번호·국가 KR), SSH 사용을 설정하세요.

이 방법에는 고정 IP 항목이 없습니다. 기록이 끝난 뒤 SD카드를 다시 꽂고 D:\network-config를 메모장 대신 VS Code로 열어(줄바꿈을 LF로 유지해야 합니다) dhcp4: false와 addresses, routes, nameservers를 직접 추가하면 됩니다.

Windows 기본 메모장으로 저장하면 줄바꿈이 CRLF로 바뀌어 부팅이 실패할 수 있습니다. VS Code나 Notepad++처럼 줄바꿈 방식(LF)을 지정할 수 있는 편집기를 쓰세요.
