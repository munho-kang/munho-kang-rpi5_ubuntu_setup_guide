A

SD카드 준비 (Claude Code)

1

준비하기

  • 노트북을 IOTCOSS1-5G에 연결합니다. 고정 IP 대역을 이 네트워크에서 읽어오기 때문입니다.
  • VPN이 켜져 있다면 끕니다. 네트워크 정보가 틀리게 읽힐 수 있습니다.
  • microSD 카드를 노트북에 꽂습니다. 카드 안의 데이터는 전부 지워집니다.
  • 터미널 창을 두 개 준비합니다. 하나는 Claude Code용, 하나는 sudo 명령을 직접 실행할 용도입니다.
2

Claude Code 실행 후 프롬프트 입력

첫 번째 터미널에서 작업 폴더를 만들고 Claude Code를 실행합니다.

터미널 1
mkdir -p ~/rpi-setup && cd ~/rpi-setup
claude

아래 프롬프트를 그대로 붙여 넣습니다. 도중에 Claude Code가 명령 실행 권한을 물으면 내용을 읽어 보고 허용하면 됩니다.

최종 프롬프트
라즈베리파이5(8GB)용 SD카드를 Ubuntu Server 24.04로 준비해줘.
노트북은 macOS(Apple Silicon)이고, SD카드는 이미 꽂혀 있어. 작업 폴더는 ~/rpi-setup 이야.

[안전 규칙 - 반드시 지킬 것]
1. 기록 전에 `diskutil list external physical`로 SD카드 후보를 보여주고 디스크 번호, 용량, 이름을 정리해줘.
   내가 "진행"이라고 답하기 전에는 절대 기록하지 마.
2. 내장 디스크(disk0 등 internal)는 어떤 경우에도 대상으로 삼지 마.
3. sudo가 필요한 명령은 직접 실행하지 말고, 확정된 디스크 번호를 넣은 완성된 명령어만 알려줘.
   내가 별도 터미널에서 실행하고 "완료"라고 알려줄게.

[1단계: 이미지 준비]
- https://cdimage.ubuntu.com/releases/24.04/release/ 에서 최신
  ubuntu-24.04.x-preinstalled-server-arm64+raspi.img.xz 를 ~/rpi-setup 에 받아줘.
- 같은 위치의 SHA256SUMS로 `shasum -a 256` 검증을 하고 결과를 보여줘. 불일치하면 중단해.

[2단계: 고정 IP 결정]
- 노트북은 지금 IOTCOSS1-5G에 연결되어 있어.
  `ipconfig getifaddr en0`, `ipconfig getpacket en0`로 노트북 IP, 서브넷 마스크, 게이트웨이, DNS를 확인해서 보여줘.
- 같은 대역에서 끝자리가 높은 번호(예: .200)를 고정 IP 후보로 제안하고,
  `ping -c 2 후보IP`와 `arp -a`로 이미 사용 중이 아닌지 확인해줘.
- 내가 승인하면 그 IP로 확정해.

[3단계: 기록 명령 안내]
- 내가 디스크를 승인하면 아래 형태의 완성된 명령을 알려줘 (N은 확정된 번호):
  diskutil unmountDisk /dev/diskN
  xz -dc ~/rpi-setup/<이미지파일>.img.xz | sudo dd of=/dev/rdiskN bs=4m
- 진행 상황은 Ctrl+T로 볼 수 있다는 것과, 끝난 뒤 "읽을 수 없는 디스크" 팝업이 뜨면 "무시"를 누르라는 것도 함께 알려줘.

[4단계: cloud-init 설정 파일 작성]
- 내가 "완료"라고 하면 system-boot 파티션(/Volumes/system-boot)이 마운트됐는지 확인하고,
  안 되어 있으면 `diskutil mountDisk /dev/diskN`으로 마운트해줘.
- 기존 user-data, network-config는 ~/rpi-setup/backup/ 에 백업한 뒤 아래 내용으로 교체해줘.

user-data (첫 줄은 정확히 #cloud-config):
- hostname: ras, manage_etc_hosts: true
- timezone: Asia/Seoul
- users: 사용자 ras 하나만 생성 (기본 ubuntu 사용자는 만들지 마)
  - plain_text_passwd: ras, lock_passwd: false
  - groups: adm, sudo, dialout, plugdev, video / shell: /bin/bash
- chpasswd: expire: false (첫 로그인 때 비밀번호 변경을 강제하지 않음)
- ssh_pwauth: true (SSH 비밀번호 로그인 허용)
- package_update: true, packages: [avahi-daemon] (ras.local 이름으로 접속하기 위함)

network-config (netplan v2 형식):
- wifis 아래 wlan0, dhcp4: false
- addresses: [확정IP/프리픽스]
- routes: to: default, via: 게이트웨이 (gateway4는 deprecated라 사용 금지)
- nameservers: 게이트웨이, 8.8.8.8
- regulatory-domain: KR
- access-points: "IOTCOSS1-5G", password: "Coss0603"

[5단계: 검증 및 마무리]
- 작성한 user-data와 network-config 전체 내용을 보여주고 YAML 문법을 검사해줘.
  (시스템 Python에 패키지를 직접 설치하지 말고, 필요하면 임시 가상환경을 써)
- 문제가 없으면 `diskutil eject /dev/diskN`으로 안전하게 꺼내줘.
- 마지막에 확정된 고정 IP와 접속 명령(ssh ras@IP)을 요약해줘.

이미지 다운로드와 체크섬 확인

Claude Code가 이미지를 받고 SHA256 값을 비교해 보여줍니다. 두 값이 같다는 결과(OK)만 확인하면 됩니다. 이미지는 1GB가 넘어서 네트워크에 따라 몇 분 걸립니다.

고정 IP 승인

Claude Code가 네트워크 정보와 IP 후보를 보여줍니다. 아래 세 가지를 확인하고 승인하세요.

  • 후보 IP가 노트북 IP와 같은 대역인지 봅니다. 예를 들어 노트북이 192.168.0.23이면 후보도 192.168.0.x여야 합니다.
  • ping에 응답이 없어야 합니다. 응답이 오면 이미 누가 쓰고 있는 IP입니다.
  • 게이트웨이 주소가 보통 .1 또는 .254로 끝나는지 봅니다.

승인했다면 아래 칸에 입력해 두세요. 이후 명령어에 자동으로 반영됩니다.

여기에 입력하면 이 아래 명령어들에 자동으로 들어갑니다.
공유기 관리 권한이 있다면 공유기의 DHCP 범위 밖 번호를 고르는 게 가장 안전합니다. 공용 네트워크라 알 수 없다면 .200 이상의 높은 번호가 대체로 안전합니다.
5

디스크 승인 (가장 중요)

Claude Code가 보여주는 목록은 대략 이렇습니다.

예시 출력
/dev/disk4 (external, physical):
   #:                       TYPE NAME        SIZE       IDENTIFIER
   0:     FDisk_partition_scheme            *63.9 GB    disk4
   1:             Windows_FAT_32 NO NAME     63.9 GB    disk4s1
  • external, physical이라고 표시되어 있는지 확인합니다.
  • 용량이 SD카드 용량과 비슷한지 확인합니다. 64GB 카드는 약 63.9GB로 표시됩니다.
  • disk0이 아닌지 확인합니다. disk0은 노트북 내장 디스크입니다.
  • 헷갈리면 SD카드를 뺐다가 다시 꽂고 목록에서 사라졌다 나타나는 번호를 찾으세요.

확인이 끝나면 Claude Code에 “진행”이라고 답하고, 아래 칸에 숫자를 입력하세요.

위에서 확인한 숫자만 입력하세요 (disk4 → 4).

이미지 기록 (직접 실행)

Claude Code가 알려준 명령을 두 번째 터미널에서 실행합니다. 아래 명령과 같은 형태인지 비교해 보세요.

터미널 2
diskutil unmountDisk /dev/diskN
xz -dc ~/rpi-setup/ubuntu-24.04*-raspi.img.xz | sudo dd of=/dev/rdiskN bs=4m
  • Password:가 나오면 Mac 로그인 비밀번호를 입력합니다. 입력해도 화면에 표시되지 않는 게 정상입니다.
  • 기록 중에는 아무것도 출력되지 않습니다. Ctrl+T를 누르면 지금까지 기록한 양을 볼 수 있습니다.
  • 보통 5~15분 걸립니다. bytes transferred 줄이 나오고 프롬프트가 돌아오면 끝난 것입니다.
  • 끝난 직후 “삽입한 디스크를 읽을 수 없습니다” 팝업이 뜨면 무시를 누릅니다. 리눅스용 파티션이라 macOS가 못 읽는 것이고 정상입니다.
rdisk 뒤 숫자를 한 번 더 보세요. 5단계에서 확인한 번호와 다르면 실행하지 마세요. 잘못된 디스크에 쓰면 복구할 수 없습니다.

기록이 끝나면 Claude Code에 “완료”라고 알려줍니다.

설정 파일 확인 후 꺼내기

Claude Code가 user-data와 network-config를 작성해 보여줍니다. 직접 한 번 더 확인하고 싶다면 두 번째 터미널에서 실행하세요.

터미널 2
head -3 /Volumes/system-boot/user-data
cat /Volumes/system-boot/network-config
  • user-data 첫 줄이 #cloud-config입니다.
  • network-config에 고정IP/24 같은 주소, IOTCOSS1-5G, regulatory-domain: KR이 들어 있습니다.
  • SSID 대소문자와 하이픈(-5G)이 정확합니다. 한 글자라도 틀리면 연결되지 않습니다.

Claude Code가 꺼내기까지 마치면 SD카드를 뽑습니다. 직접 꺼내려면 아래 명령을 씁니다.

터미널 2
diskutil eject /dev/diskN

부팅과 원격 접속

8

첫 부팅

  • microSD 카드를 라즈베리파이5 뒷면 슬롯에 끼웁니다.
  • 전원을 연결합니다. 공식 27W(5V 5A) USB-C 어댑터를 권장합니다. 일반 충전기를 쓰면 USB 전력이 제한된다는 경고가 뜰 수 있습니다.
  • 5분 정도 기다립니다. 첫 부팅 때 cloud-init이 사용자 생성, Wi-Fi 설정, avahi 설치를 진행합니다. 이 동안 초록 LED가 불규칙하게 깜빡입니다. 중간에 전원을 뽑지 마세요.
9

SSH 접속

노트북이 같은 Wi-Fi(IOTCOSS1-5G)에 연결되어 있는지 확인한 뒤, 먼저 응답이 오는지 봅니다.

노트북 터미널
ping -c 3 고정IP

응답이 오면 접속합니다.

노트북 터미널
ssh ras@고정IP
  • 처음 접속하면 Are you sure you want to continue connecting가 나옵니다. yes를 입력합니다.
  • 비밀번호 ras를 입력합니다. 화면에는 표시되지 않습니다.
  • 프롬프트가 ras@ras:~$로 바뀌면 접속 성공입니다.

IP 대신 이름으로도 접속할 수 있습니다. avahi 설치가 끝난 뒤부터 됩니다.

노트북 터미널
ssh ras@ras.local

접속 후 점검

라즈베리파이에 접속한 상태에서 아래를 차례로 실행합니다.

라즈베리파이 (ras@ras)
cloud-init status --wait        # status: done 이 나와야 함

업데이트는 처음에 10분 이상 걸릴 수 있습니다. 재부팅 후 1분쯤 지나 다시 접속하세요.

비밀번호 ras는 공용 네트워크에서 쉽게 뚫립니다. 접속한 뒤 passwd로 더 긴 비밀번호로 바꾸는 걸 권장합니다.

문제 해결

Claude Code가 sudo 비밀번호 입력에서 멈춰 있음

Claude Code 안에서는 비밀번호를 입력할 수 없습니다. Esc로 멈춘 뒤 “sudo 명령은 명령어만 알려줘”라고 다시 요청하고, 두 번째 터미널에서 직접 실행하세요.

dd 실행 시 Resource busy 오류

SD카드가 아직 마운트되어 있는 상태입니다. diskutil unmountDisk /dev/diskN을 먼저 실행한 뒤 dd를 다시 실행하세요.

기록 후 /Volumes/system-boot가 보이지 않음

SD카드를 뺐다가 다시 꽂거나 diskutil mountDisk /dev/diskN을 실행하세요. Finder 사이드바에 system-boot가 보이면 정상입니다.

ping에 응답이 전혀 없음

먼저 2~3분 더 기다리고, 그래도 안 되면 전원을 한 번 껐다 켜세요. Ubuntu는 첫 부팅 때 Wi-Fi가 늦게 잡히는 경우가 있어 재부팅으로 해결되는 일이 많습니다.

계속 안 되면 모니터와 키보드를 연결해 ras / ras로 로그인한 뒤 확인합니다.

라즈베리파이 (직접 연결)
ip a show wlan0
sudo cat /etc/netplan/50-cloud-init.yaml
sudo netplan apply

wlan0에 IP가 잡혀 있는데도 노트북에서 접속이 안 된다면, 네트워크에 AP 격리(기기끼리 통신 차단)가 켜져 있을 수 있습니다. 네트워크 관리자에게 문의하거나 랜선을 노트북과 직접 연결해 우회하세요.

Permission denied (비밀번호가 틀렸다고 나옴)

cloud-init이 아직 사용자를 만들지 않았을 가능성이 큽니다. 몇 분 더 기다린 뒤 다시 시도하세요. 그래도 안 되면 SD카드를 노트북에 다시 꽂아 user-data의 첫 줄이 #cloud-config인지, 들여쓰기가 맞는지 확인합니다.

REMOTE HOST IDENTIFICATION HAS CHANGED 경고

SD카드를 새로 구우면 서버 키가 바뀌어서 나오는 경고입니다. 예전 기록을 지우고 다시 접속하세요.

노트북 터미널
ssh-keygen -R 고정IP
ssh-keygen -R ras.local
ras.local로는 접속이 안 되고 IP로는 됨

첫 부팅 때 인터넷이 늦게 연결되어 avahi 설치가 빠졌을 수 있습니다. IP로 접속한 뒤 sudo apt install -y avahi-daemon을 실행하세요.

터미널에서는 되는데 VS Code만 연결이 안 됨 (No route to host)

macOS의 로컬 네트워크 권한 문제입니다. 시스템 설정 → 개인정보 보호 및 보안 → 로컬 네트워크에서 Visual Studio Code를 켜고 VS Code를 다시 실행하세요.

고정 IP가 다른 기기와 충돌함

SD카드를 노트북에 꽂고 /Volumes/system-boot/network-config의 addresses만 다른 번호로 바꾸면 됩니다. 이미 부팅한 뒤라면 라즈베리파이에서 /etc/netplan/50-cloud-init.yaml을 수정하고 sudo netplan apply를 실행하세요.

Claude Code 과정이 막히면 Imager에서 직접 해도 됩니다. 장치는 Raspberry Pi 5, OS는 Other general-purpose OS → Ubuntu → Ubuntu Server 24.04.x LTS (64-bit)를 고릅니다. 저장소에서 SD카드를 선택한 뒤 OS 커스터마이징에서 hostname, 사용자, Wi-Fi, Wi-Fi 국가(KR), SSH를 설정하세요.

GUI에는 고정 IP 항목이 없습니다. 기록이 끝난 뒤 SD카드를 다시 꽂고 /Volumes/system-boot/network-config를 열어 dhcp4: false와 addresses, routes, nameservers를 직접 추가하면 됩니다.
